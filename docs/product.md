## 1. Продукт

### 1.1 ЦА

- **Основная [гипотеза H1]:** соло-мейкеры веб-приложений, мобильных приложений и игр, которые строят с AI-агентами
  (Claude Code, Codex, Cursor и подобные), у которых уже есть подписки на эти инструменты.
- **Их день [гипотеза H2, §199]:** инди-мейкер с основной работой: утром и вечером запускает продукт и даёт фидбек, днём
  набрасывает идеи с телефона, ночью строится. Мало двух вещей: токенов и времени.
- **Вход через игру [гипотеза H3]:** «лагерь орков» приводит людей лучше, чем офисный вид; тёплая настольная эстетика —
  крючок для инди-геймдева (§148: «тёплая основа настольной игры, знакомая инди-разработчикам, для которых он»).
- **Не ЦА (пока):** команды с Jira/Slack-процессами (Team убран, §122.2); люди, которые хотят no-code-конструктор.

### 1.2 Проблема

1. **Узкое место — не код, а «что именно нужно» [H1].** Агенты пишут код всё лучше и дешевле; соло-мейкер теряет время между
   «чего я хочу» и «что агент построил»: что, зачем, где граница, что значит *готово*.
2. **Спеки пишутся из промпта, а не из продукта.** Агент планирует по описанию, не видя реальный код и работающий продукт:
   план расходится с тем, что есть.
3. **Никто не говорит «нет».** Один агент соглашается со всем; нет голосов продукта, дизайна, релиза, которые бы
   возразили до того, как потрачены токены.
4. **Решения теряются.** Почему сделали так — живёт в чатах; через неделю новая цель противоречит старому решению, и никто
   этого не видит.
5. **Лимиты непрозрачны.** Сколько стоит цель в недельном окне Claude или Codex — не видно, пока окно не кончилось.

### 1.3 Наше решение

**Студия, которая видит твой реальный продукт** (H1): стол лидеров — продукт, дизайн, тех, арт, маркетинг, релиз — судит
каждую цель против реального кода и работающего продукта, говорит «нет» там, где больно, а то, что решил человек, отдаёт
*его же* AI-инструментам строить и проверять. На десктопе, в VS Code и на сопряжённом телефоне (README).

- Карты лидеров читаются из кода без модели (System у Теха, экраны и их поток у Дизайна, спеки 89, 102).
- Несогласие — фича: «нет» лидера, развилка к человеку, решение в логе (спеки 99, 108).
- Вся студия, а не только инженерия: отряды по стадии проекта (§122.5).
- Петля замкнута: что нужно → спека → работа любого агента → гейт → живой продукт → пометка → что нужно.
- Свои подписки (мана), без нового счёта за модели; всё в репозитории проекта (`docs/decisions.md`, `orkcraft.toml`).
- Без приложения: доска — это файлы, любой AI-инструмент работает с ней по `AGENTS.md` (§255, спека 151).

### 1.5 Use Cases

1. **Новая фича в существующем проекте.** Человек пишет цель в + карту → Оркмастер ведёт её по маршруту → Talk лидеров →
   решение в логе → секции спеки → работа орков в ветках → гейт → сброс → человек отправляет в main (спека 99, §274).
2. **Баг.** Короткий путь: только Тех, его Talk — диагноз; если баг уже воспроизводится — сразу в работу (README, спека 119).
3. **Быстрый вопрос о проекте.** «Почему у нас так сделан вход?» — одна строка на открытой вкладке, ответ Оркмастера или
   лидера, ничего не меняется (спека 106, §181).
4. **Идея с телефона днём.** Набросок цели с телефона → вечером/ночью она идёт в работу по сбросу лимитов (H2, §199, §245).
5. **Похожая идея уже лежит.** Новая цель сверяется с лежащими «рубашкой вверх»; человек решает: *Добавить к ней* или
   *Оставить отдельно* (спека 135, §242).
6. **Новая цель противоречит старому решению.** Оркмастер бросает карту конфликта до подтверждения (§254.6).
7. **Посмотреть продукт глазами лидера.** Вкладка Дизайна — экраны по потоку; Теха — система; Продукта — дерево и боли;
   «вид» лидера: что работает, что болит, что дальше (§280, §282, спека 167).
8. **Попробовать, что сделали орки, до main.** ▶ Play запускает превью dev (§193, §246).
9. **Тот же Board в Claude Code / Codex / Cursor без приложения** (§255, спека 151).

### 1.6 Сущности продукта

#### Оркмастер
Говорит **что** делается и **кто** делает (§104.0). Его вкладка — весь проект, его карта — **Board**: дорожка на отряд,
цель — каскад задач; первая дорожка — цели, которые он читает, маршрутизирует, объединяет, и цели *в очереди* (§143, §206).
Он: прокладывает маршрут цели (сначала кодом, без модели; моделью — только если код не нашёл отряд, на дешёвом тире,
спека 99 §4); формулирует решение после Talk; бросает карты (конфликт §254.6, первые четыре карты при открытии §254.8);
сверяет новую цель с лежащими (спека 135); следит, чтобы отряды не трогали одни файлы (спека 71); читает решения перед
маршрутом (§281.7, цель 166 — в Talk). Раскладывает по стадии проекта, какие ремёсла за столом (§266.7).

#### Лидеры и их столы
Лидер отряда говорит **как**, что меняется и почему (§104.0). Ремесло отряда — его раса (§53, §158): орки — Тех, эльфы —
Дизайн и Арт, гоблины — Run/LiveOps, гномы — маркетинг, рыцари — Продукт (в игре — геймдизайн), нежить — релиз. Лидер — высшая
форма расы (орк-шаман, эльф-дриада, золотой рыцарь-единорог, лич…).
- **Лидер — герой школы** (§266.3): фреймворк ремесла, его поток работы, размер, *сколько решает сам*, *как часто говорит
  «нет»*, цена — как статы на карте героя; 3–6 героев на ремесло, звёздочкой — выбор Оркмастера.
- **Стол лидера** — его карта продукта (§254: на вкладке — *стол*): Тех — System из кода без модели; Дизайн — экраны по
  потоку; Продукт — дерево и боли; Геймдизайн — луп; Арт — ассеты; Релиз — dev против main. Тепло на частях, охват цели до
  старта (§280). Вид продукта глазами лидера (§282).
- **Что лидер делает с целью:** Talk (позиция, за и против, вопросы), своя секция спеки, план шага отряда, приёмка шага
  против своей секции, отдельным проходом (§256, спека 152). Говорит «нет» и показывает, где болит (спека 108).

#### Команда и флоу работы
- **Отряд = лидер + минимум один, кто делает** (§256). Шапка отряда — его отряд: кто **Делает** (меч) и кто **Проверяет**
  (щит), у каждого места свой AI-инструмент и тир (§201.4).
- **Член отряда делает и спрашивает только своего лидера**: вопрос члена доходит до человека только как развилка лидера.
- **Таскмастер** разбивает работу цели на этапы; **Грунт** делает задачу — целую сессию, в своей ветке (§257).
- **Путь цели:** `new` → `talk` → `spec` → `work` → `done` (спека 99, BOARD.md).
  1. Маршрут: Оркмастер кладёт в руку карту маршрута — кто обсудит, сколько стоит, место в очереди. Ничего не вызывается до *Talk*.
  2. Talk: каждый лидер маршрута отвечает коротко; человек отвечает в руке; максимум два круга; решение пишет Оркмастер,
     *Подтвердить и начать* записывает его с номером в `docs/decisions.md`.
  3. Spec: каждый лидер пишет свою секцию: *Why, Done when, Checks, Will be, Out, Risks*; где секции расходятся — развилка.
  4. Work: каждый отряд планирует свой шаг, орки работают в своих worktree, проверки, приёмка лидером.
  5. Done: гейт зелёный, цель в **сбросе** (discard), «обещано против сделано»; в main — только руками человека (§274).
- **Мана**: лимиты AI-инструментов как зелья справа от руки; цена цели словами («около 4% недели Claude») до траты;
  *Позже, само* — цель ждёт сброса окна (§107.1, спеки 104, 114).
- **Stop all** — одно нажатие останавливает всех орков (§126.1, §261).

#### Карты и диалоги с лидерами
- **Цель — это карта**: на столе, в руке или в сбросе (§167, §176). Ожидая — лежит рубашкой вверх; в игре — стоит лицом;
  4 угла несут смысл (§251, спека 147).
- **Рука** — только то, что решает человек: провал, план, вопрос, выбор вариантов, конфликт. Нет счётчиков ожидания (§67).
- **Вопрос лидера** — карта на 2–4 варианта, один уже выбран с причиной (BOARD.md «A question for the person»).
- **Пузырь лидера**: голова лидера нажата → его пузырь: быстрый вопрос, ответ, вечерняя строка (§201).
- **Карта поднята** — переворачивается: её обратная сторона говорит, что сделано, и открывает diff, лог или файл (§270).

### 2.1 Создание новой карты [есть: спеки 99, 135, §254, §264]
- **+ карта** в руке растёт в поле: пишешь цель; адресуешь отряду через *@Tech* или открытой вкладкой; вставляешь
  картинку; указываешь на часть карты (углы, чтобы выбрать, §254); *Сейчас* или *Позже*.
- При отправке: маршрут — кодом, без вызова модели; поле само говорит, если похожая цель уже лежит (*Добавить к ней* /
  *Оставить отдельно*, спека 135); мана показывает цену.
- На телефоне — то же поле, рука первой (спеки 53, 136).

### 2.2 Взаимодействие со столом лидера [есть: §254, §266, §280, §282]
- Вкладка = лидер; две оси: **что смотрим** (весь проект или выбранная цель) и **чьими глазами** (вкладка). Заголовок
  панели говорит обе: *Волны · глазами Теха* (§110.1, §145.5).
- Стол лидера показывает его карту; выбранная цель — точки на вкладках отрядов её маршрута; тепло и охват цели (§280).
- Голова в шапке → поповер места: роль, инструмент, тир, цена, *Со следующей задачи*, *Undo* (§110.7).
- Лич у портала → прошлое через открытую вкладку: последние решения ремесла пирамидой (§254).
- Вид лидера на продукт — работает / болит / дальше; облик выбирается на мокапах (спека 167, в работе).

### 2.3 Задать вопрос лидеру или Оркмастеру [есть: спека 106, §181, §259]
- **Быстрый вопрос**: одна строка на открытой вкладке; отвечает тот, чьими глазами смотрит вкладка (Оркмастер на своей,
  лидер — на вкладке отряда). Это чтение: нет карты, нет фазы, ничего не меняется. Ответ 2–6 строк, с источниками;
  *Сделать целью* превращает вопрос в цель.
- Ответ — только из того, что есть (доска, карта лидера, решения); если там этого нет — так и говорит и где искать.
- Сейчас только десктоп (§181.8).

### 2.4 Поиск по сделанным решениям [есть: спека 134 A.6, §238.3, §277]
- **Поиск по хронике**: по заголовкам целей, их спекам и решениям; каждое слово запроса должно найтись; без модели.

- Экспорт решений в MADR / Nygard: `orkboard export --as madr` (спека 126).

### 2.5 Определение конфликтов между решениями [есть частично]
- **Новое решение против старого [есть: §254.6, `realm/decision_conflicts.py`]**: вызов, формулирующий решение цели, сам
  называет до двух стоящих решений, против которых оно идёт. Оркмастер бросает **карту конфликта** до подтверждения; старое
  решение выходит из портала рядом. Ответы: *Заменить §N* / *Оставить §N* (цель обсуждается снова в рамках §N) /
  *Другое…*. Пока конфликт открыт — решение не подтвердить. Решение никогда не переписывается — конфликт с ним всегда
  спрашивается (§266.6).
- **Секция против прошлой спеки [есть: §266.6]**: у лидера — *Спросить* / *Объявить* (переписывает и кладёт карту с *Undo*)
  / *Молча* (в вечерней строке).
- **Две цели в одних файлах [есть: спека 71]**: коллизия против совпадения — дешёвый вызов после планов.
- **Похожие цели [есть: спека 135]**: сверка по словам, без модели.
- **Нет**: аудита всего лога на внутренние противоречия (решение §A против §B, принятых давно).

### 2.6 Настройки лидеров и проекта [есть: §266, §267]
- **Инвентарь** (рюкзак после вкладок): вкладка выбрана → стол раскладывает, *как проект настроен*; вещь нажата → её
  варианты в руке, каждый с ценой в зельях; наведение показывает вариант на месте; *Undo*; брошенная в сброс — возврат к
  дефолту. *Твоё* / *Твоё раньше* / звезда Оркмастера.
- **Лист Оркмастера**: *Когда* (стартуют ли High/Normal/Low цели сейчас, по неделе, ночью, руками; *Когда я тут*),
  *Сколько* (глубина, дневной лимит авто-ответов), *Что уходит с этого компьютера* (push после merge, облачный запуск —
  деньги словами), *Вопросы Оркмастера*.
- **Лист лидера**: его герой, его вопросы, его конфликты со спекой, AI-инструмент и тир каждого места.
- **Settings … — сантехника**: входы, доска в репозитории, правила для любого AI-инструмента, телефон, не спать,
  обновления, логи. Гейт — в `orkcraft.toml`.
- Риск всё равно решает, может ли работа стартовать без человека (§57.3).

### 2.7 Паттерны выбора вариантов со стороны пользователя [есть: §266.5, §259, BOARD.md]
- **Четыре способа ответа**: **Перо** (свои слова), **Выбор** (варианты лидера; «если не посмотришь за N — выбор
  лидера»), **Развилка** (3–4 проработанных пути, каждый нарисован на столе, выбор лидера отмечен, *Другое…* → Перо; стоит
  маны и говорит это), **Молча** (лидер решает сам и говорит в вечерней строке).
- **Всегда один вариант уже выбран** — с причиной; у каждого варианта строка до 80 символов: к чему он ведёт.
- **Заперто на Перо / Выбор / Развилку**, никогда Молча и никогда ожидание: уход в main, деньги сверх согласованного,
  сброс или Hold цели, решение против прежнего.
- Вопрос, который уже решает записанное решение или спека, не задаётся человеку — отвечается ссылкой (§259).
- Ночь предлагает шаг вверх от того, как человек отвечал (§51.4); принять или нет — его.
- Герой приносит свои способы; то, что задал человек, — его и переживает героя.

## 3. Tech

### 3.1 Быстрый и дешёвый первый этап обсуждения (assessment идеи) [есть: спеки 99, 135, 86, `realm/idea_target.py`]
- **Маршрут — кодом, без модели**: адресованный отряд, баг → Тех, типы целей по словам, один отряд. Только если код не нашёл
  отряд — один вызов Оркмастера на самом дешёвом тире (`route`: laborer при thrift).
- **Сверка с лежащими — кодом** (спека 135): ни одного вызова, меньше отдельных Talk.
- **Talk**: по вызову на лидера маршрута, все сразу, на дешёвом тире (`talk_round`: laborer / warrior-low / warrior-medium по
  Target thrift / balance / quality); ответ короткий (позиция, за, против, вопросы); максимум два круга.
- **Контекст обрезан** (`idea_target.cut`): у маршрута ~2500 символов.
- **Мана до траты**: цена цели словами до того, как что-то тратится; при нехватке Оркмастер предлагает короткий путь или
  *Позже, само*.
- Замер из пробного прогона (§250): Talk выслушал лидера примерно за 15 тыс. токенов; дорого стоила работа, а не мысль.
- Быстрый вопрос — без инструментов, только чтение (спека 106).

### 3.2 Подготовка документации по всем необходимым лидерам [есть: спеки 99, 124, 125, 151, 154]
- **Спека цели = секции лидеров** в странице цели (`llm-wiki/general/pages/ideas/<slug>.md`): Why, Done when (с тем, как
  доказано: [test] / [look] / [person]), Checks, Will be, Out, Risks; спека-файл в `docs/specs/` пишется вместе со
  страницей цели (§255.17).
- **Лог решений** `docs/decisions.md`: нумерованный, прошлое не правится, новое говорит *Changes: N*.
- **Бриф проекта** (спека 124): шесть строк, которые читает каждый лидер — для кого, что болит, что оставляет за бортом,
  почему это, каким должен быть всегда, как зарабатывает; две сессии вопросов.
- **Журналы** `journals/<party>.md`: что отряд узнал, строка на запись; дайджест.
- **Роли** `roles/<id>.md`: что сказано каждому месту; одно с промптом; в Claude Code — subagent + skill (§258).

- **Импорт / экспорт**: `orkboard import` читает документы проекта; `orkboard export` пишет решения, бриф, журналы в
  MADR / Nygard (спека 126).
- **Для любого AI-инструмента**: `AGENTS.md` + `BOARD.md` + `roles/` (спека 151).
